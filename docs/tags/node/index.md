# 节点相关内容

<AnswerBox />

节点是订阅列表里的一条具体服务器配置，包含地址、端口、协议类型与加密参数。它回答的是「怎么连接」，而不是「数据走哪条路」—— 后者属于线路的范畴。把这两件事分开，是理解绝大多数使用现象的前提。

最常见的误解出在名称上。节点名称里的地区标记只是服务商的命名习惯，它通常只表示**出口**在哪，既不说明入口在哪，也不说明中间经过了什么。这就是为什么两个都写着「香港」的节点，体验可以相差好几倍：它们的出口地区相同，国内段和跨境段却可能完全不是一回事。要确认真实出口，唯一可靠的方法是连接后查询实际 IP 的归属。

另一个反直觉的点是数量。节点列表长不代表质量高 —— 数量只说明这份列表有多长，不说明每条线路的容量与共享程度。少量结构清晰、共享程度低的节点，通常好过大量被严重超售的节点。同理，「换了几十个节点都没用」往往不是因为节点不够多，而是因为这些节点共享同一个入口或同一批上游资源，换来换去始终没离开出问题的那一段。

这个标签聚合的内容围绕三件事：节点与线路的层级关系、如何确认真实出口与出口类型、以及节点相关异常（全部超时、部分不可用、名称与实际不符）应该往哪个方向排查。
